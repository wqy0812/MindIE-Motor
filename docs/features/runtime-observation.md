# Runtime observation

The Coordinator management server and Conductor expose a bounded read-only `GET /runtime` summary when `MOTOR_RUNTIME_TARGET_ID` is configured. The response schema is `motor-runtime-v1`. Protect management listeners with the same network policy as existing readiness/health endpoints; an external observer fetches the fixed local endpoint. This endpoint has no service-control, token payload, log traversal, subscription-completeness or index traversal capability.

For Coordinator, also set `MOTOR_RUNTIME_STATE_DIR` to a persistent directory owned by the service, with mode 0700. Preserve it across worker/container replacement. It stores only a target/worker query-fault latch, atomically and on transitions, with 0600 files. An unreadable/corrupt state, including valid JSON with the wrong top-level type, reports incomplete coverage while allowing worker initialization. Only an actual successful business query clears a confirmed query fault. Idle healthy workers do not need synthetic queries.

Each inference worker keeps its own boot identity, bounded result/decision counters, last real query success/failure and consecutive failure streak. Three consecutive actual failures latch a query fault. Circuit-open skips are counted separately and do not extend the streak. Counters are never summed to manufacture a failure threshold. Actual committed affinity/load-balance decisions are counted at the successful allocation point; a query-failure fallback is confirmed only by a subsequent committed load-balance allocation.

A five-second background task sends bounded snapshots through the existing local management IPC, with a one-second RPC timeout and cancellation during disconnect. Each snapshot carries `sampled_at_monotonic_seconds` from the shared host monotonic clock. Management validates this source time, bounded worker slots and boot/start/sequence identity, rejecting missing/invalid/future timestamps and out-of-order updates. Worker age includes time spent in IPC; receiving an old message does not renew its 15-second validity. Stale workers reduce coverage but keep previously confirmed query fault evidence. A new process identity alone does not resolve a query fault.

The Conductor summary uses process-start identity and fixed-size atomic counters for real `/query` and `/query_by_hash` results (success/rejected/failed). It does not scan workers or indexes. Registration completeness and processing progress remain unsupported optional diagnostics. Current HTTP readiness and real queries provide the stated evidence; this summary does not claim subscriber/index correctness.

Deployment keeps runtime identity and resource collection separate from this opt-in native profile. Consumers should treat missing required observations as unknown, report resource risk independently, and preserve failure plus observation gaps. Do not interpret an old cumulative OOM or a single query error as a current service failure.

Validation: `bash tests/run_tests.sh --serial tests/coordinator/test_runtime_observation.py tests/coordinator/api_client/test_conductor_api_client.py -k runtime`; native `cargo test --offline --locked runtime_observation`, `cargo clippy --offline --locked --all-targets -- -D warnings`. Run the Python test runner with a GNU-compatible sed on macOS because its protobuf generator uses GNU `sed -i` syntax.
